# Security Policy

## Supported versions

Security fixes are provided for the current release.

| Version | Supported |
| --- | --- |
| 1.0 | Yes |
| Older releases | No |

1.0 is the supported release. Reports against older copies will not be addressed unless they also affect 1.0.

## Reporting a vulnerability

Report security issues privately. Do not open a public GitHub issue, discussion, or pull request for a suspected vulnerability.

Use GitHub private vulnerability reporting, which opens a draft security advisory only the maintainers can see:

[Report a vulnerability](https://github.com/connor-sec/ethical-docs/security/advisories/new)

You need a GitHub account. The same form is linked from the repository **Security** tab as **Report a vulnerability**. GitHub's description of the process is [Privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).

Include the file you tested (`Ethical_Invoice.html` or `Ethical_WorkOrder.html`), the version or tag, what you observed, and how to reproduce it. Please give the maintainer time to respond before any public disclosure.

## Authorized use

Ethical Docs is a pair of offline invoice and work-order generators for authorized security research and education. Use them only inside an expressly authorized and documented testing scope. They format documents from values you enter and keep that work in the browser. Creating or distributing invoices or work orders for fraud, unauthorized access, or pretexting without consent may violate law, contract, or organizational policy. A generated document is not permission to be on a site.
